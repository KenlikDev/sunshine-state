# Architecture Decision Records

Record decisions that materially affect architecture, tooling, formats, or production workflow.

Use one numbered file per decision, for example `0001-engine-and-language.md`.

Each record should include:
- Status: proposed, accepted, superseded, or rejected
- Context and constraints
- Decision
- Alternatives considered
- Consequences and risks
- Validation plan
- Date and participants

Do not treat a proposed decision as accepted until reviewed.
